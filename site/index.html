How it works

The case study behind this page

  1. Collect. Every weekday evening (with a retry and a next-morning check), a GitHub Actions job fetches end-of-day prices for 25 stocks from Yahoo Finance and upserts them into PostgreSQL (hosted on Neon).
  2. Compute in the database. A PL/pgSQL function uses window functions to calculate momentum, volatility, 50/200-day averages, RSI, volume z-scores, trend and anomaly flags for every stock and day.
  3. Check. Eight automated data-quality checks (freshness, impossible prices, missing days, signal coverage…) stop the pipeline if anything looks wrong. Triggers record every change in an audit log.
  4. Publish. A materialized view pre-aggregates sector data; a script exports it to static JSON and this site is rebuilt. The website never connects to the database.

Frequently asked questions

Is this real-time data?

No. It uses end-of-day prices: the database is updated every weekday evening after the NSE closes, with a second attempt later that night and a final check the next morning. Holidays and weekends have no new data.

Where does the data come from?

Daily prices come from Yahoo Finance via the open-source yfinance library, stored in a PostgreSQL database. Prices are adjusted for splits and dividends where available.

What do momentum, RSI and "trend" mean?

Momentum is the return over the last 20 (or 60) trading days. RSI (0–100) compares recent gains with losses; above 70 is often called overbought, below 30 oversold. Trend is UP when price is above its 50-day average, which is above its 200-day average, and DOWN when the reverse is true.

What counts as an anomaly?

A day is flagged when the price move is more than 3 times the stock's typical daily move over the previous 20 days, or when trading volume is more than 3 standard deviations above its recent average. Results days, big news and index rebalances often show up here.

Does the backtest mean the strategy works?

No. It's an educational exercise: it ignores trading costs, taxes and slippage, and past performance doesn't predict the future. It shows the kind of analysis the database makes easy.

Is this investment advice?

No. This is a student DBMS project for learning. Nothing here is a recommendation to buy or sell anything.

Can I run this myself?

Yes. The full code, SQL and setup steps are on GitHub. You need a free PostgreSQL database (for example on Neon) and a GitHub account.
